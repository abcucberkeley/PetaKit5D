# PetaKit5D tests

Automated tests for PetaKit5D, written with the MATLAB unit test framework
(`matlab.unittest`). They run on small synthetic data generated by the tests
themselves, so they need no downloads and finish in minutes on a laptop or a
GitHub Actions runner. CI runs them on Linux, Windows and ARM macOS.

## Running the tests

From the PetaKit5D root folder in MATLAB:

```matlab
addpath tests
run_tests                              % everything (except known issues, see below)
run_tests('folder', 'decon')           % one area: tests/decon
run_tests('name', '*Zarr*')            % by test name (wildcards allowed)
run_tests('tag', 'Unit')               % fast function-level tests only
run_tests('excludeTag', 'Slow')        % skip the slower tests
results = run_tests('outputDir', 'test-results');   % also writes JUnit XML
```

`run_tests` returns a `matlab.unittest.TestResult` array. `assertSuccess(results)`
throws if any test failed. To debug a single test, run it with
`run_tests('name', 'DeconFunctionTest/deltaPSF*', 'verbosity', 'Detailed')`.

On the Slurm cluster, run on a compute node rather than the login node, e.g.:

```bash
srun -c4 --mem=16G --account=co_abc --partition=abc --qos=abc_normal \
    matlab -batch "addpath('tests'); assertSuccess(run_tests)"
```

Tests write only to temporary folders (`tempdir`, node-local `/tmp` on the
cluster) and never submit Slurm jobs: `pktest.NoSlurmFixture` hides `sinfo`,
`sbatch`, `squeue` and `scancel` while tests run.

### Tags

| Tag | Meaning |
|---|---|
| `Unit` | One function on in-memory data. Seconds. |
| `Integration` | A file- or dataset-level wrapper (e.g. `XR_decon_data_wrapper`) on a small synthetic dataset, run locally (`parseCluster=false`). |
| `Golden` | Compares outputs with stored reference outputs (see below). |
| `Slow` | Takes more than ~30 s. |
| `GPU` | Needs a CUDA GPU; reported as incomplete (skipped) without one. |
| `DemoData` | Runs on the published demo dataset; skipped unless `PETAKIT5D_DEMO_DATA` is set (see below). |
| `Cluster` | Submits real Slurm jobs; skipped unless `PETAKIT5D_TEST_SLURM_CONFIG` is set (see below). |
| `KnownIssue` | Checks the correct behavior for a bug that is not fixed yet (see below). |

Tests that need something the machine doesn't have (a GPU, or a mex file
that isn't built for the platform) are reported as *incomplete* instead of
failing, and don't fail `assertSuccess`.

### Real data

`tests/demo_data/DemoDatasetTest.m` checks the readers/writers, deskew/rotation
and OMW deconvolution on a tile of the light sheet demo dataset (downloaded
with `demos/demo_data_downloader.m`). It only reads the dataset and needs about
16 GB of RAM. Point `PETAKIT5D_DEMO_DATA` at the folder that contains
`PetaKit5D_demo_cell_image_dataset`:

```matlab
setenv('PETAKIT5D_DEMO_DATA', '/path/to/Downloads')
run_tests('tag', 'DemoData')
```

In Jenkins, the same command can run next to the existing demo stages, e.g.
on Linux:

```bash
srun -c8 --mem=64G --account=co_abc --partition=abc --qos=abc_high bash -c \
  "cd $PETAKIT5D_FOLDER && PETAKIT5D_DEMO_DATA=$(dirname $DEMO_DATA_FOLDER) \
   matlab -batch \"addpath('tests'); assertSuccess(run_tests('outputDir', 'test-results'))\""
```

and with `junit 'test-results/test-results.xml'` to show the results in
Jenkins. The same MATLAB command works on the Windows and Mac Jenkins
machines.

### Slurm cluster mode

All other tests run the job framework locally (`parseCluster=false`).
`tests/cluster/SlurmClusterTest.m` tests cluster mode: tasks submitted with
`sbatch`, polled with `squeue`, task batches, resubmission with more CPUs,
the final output check, and (optionally) MATLAB tasks and a data wrapper
running as jobs. The tests submit real jobs, so they only run when these
environment variables are set:

| Variable | Meaning |
|---|---|
| `PETAKIT5D_TEST_SLURM_CONFIG` | Required. JSON cluster configuration passed to the framework as `configFile` (`SlurmParam`, `MatlabLaunchStr`, `maxCPUNum`, `memPerCPU`); see `tests/cluster/github_actions_slurm.json`. |
| `PETAKIT5D_TEST_SLURM_SCRATCH` | Folder on storage the compute nodes can reach, for test data and job logs (default `tempdir`, which only works on a single-node cluster). |
| `PETAKIT5D_TEST_SLURM_MATLAB` | `true` to also run the tests whose jobs start MATLAB. |

For example, on the lab cluster (from a compute node):

```matlab
setenv('PETAKIT5D_TEST_SLURM_CONFIG', '/path/to/abc_slurm_config.json')
setenv('PETAKIT5D_TEST_SLURM_SCRATCH', '/clusterfs/fiona/<user>/pk5d_test_scratch')
setenv('PETAKIT5D_TEST_SLURM_MATLAB', 'true')
run_tests('tag', 'Cluster')
```

with a configuration like

```json
{
    "SlurmParam": "-p abc --qos abc_normal -n1 --mem-per-cpu=4G",
    "MatlabLaunchStr": "module load matlab/r2024b; matlab -nodisplay -nosplash -nodesktop -nojvm -r",
    "maxCPUNum": 24,
    "memPerCPU": 4
}
```

Each test names its jobs `pk5dtest_<id>` and cancels them when it ends.

## Continuous integration

`.github/workflows/tests.yml` runs `run_tests` on every push and pull request
(and weekly) on `ubuntu-24.04`, `windows-2025` and `macos-15` (Apple
silicon) with MATLAB R2024b. The same jobs also run with R2026b; these are
allowed to fail and preview the migration. To switch releases, edit the
`release` list in the workflow. Results are on each job's summary page,
and JUnit XML files are uploaded as artifacts.

Because MATLAB doesn't shut down cleanly on Windows and macOS (see Known
issues), the CI command ends with `pktest.finishCI`, which writes
`test-results/status.txt` and then stops MATLAB on those platforms; the next
step fails the job if tests failed or the status file is missing.

A separate job sets up a single-node Slurm cluster on the Ubuntu runner
(`tests/cluster/setup_github_actions_slurm.sh`, Ubuntu's Slurm 23.11 without
an accounting database) and runs the `Cluster` tests there with bash tasks;
jobs can't start MATLAB on GitHub (see below), so the MATLAB task tests run
on the lab cluster.

MATLAB is licensed automatically for public repositories by the
`matlab-actions` steps, and only inside them. The runners have no GPU, so `GPU` tests are skipped
there; run them on a GPU node (`srun --gres=gpu:1 ...`).

## Known issues

Some tests check behavior that is currently broken. They are tagged
`KnownIssue`, contain a `KNOWN ISSUE:` comment with the cause and a suggested
fix, and are excluded from the default run, so CI stays green while the
issues are tracked. Run them with:

```matlab
run_tests('tag', 'KnownIssue')
```

CI also runs them in a separate, non-blocking step. When a known issue is
fixed, its test starts passing: remove the `KnownIssue` tag so it guards
against the bug coming back.

Current known issues (found while writing these tests; each was confirmed by
running the test). The test name is the place to start; its `KNOWN ISSUE:`
comment has the details.

**High impact**

| Test | Problem |
|---|---|
| `DeskewMexSourceTest` | The AVX loops in the deskew/rotation mex files (`volume_deskew_rotate_warp_mex.cpp:66`, `skewed_space_interp_volume_deskew_rotate_warp_mex.cpp:105,139`, `skewed_space_interp_defined_stepsize_mex.c:103,137`) run up to 7 floats past each row. On Linux/Windows, single-precision input whose first dimension is not a multiple of 8 corrupts memory and can crash MATLAB. |
| `DeskewRotateFrame3DTest/objectiveScanPreservesContent` | Combined deskew/rotation of objective scan data returns an all-zero volume (`volume_deskew_rotate_warp_mex` assumes sample scan). |
| `MexPackagingTest` | 15 ARM macOS mex files and the bundled `libcppZarr.dylib` load Homebrew's `libgomp` by absolute path; without Homebrew gcc@13 they only load if cpp-tiff/cpp-zarr was used first in the session. |
| `TiffIOTest/rangeReadOfImageJStack` | Range reads of single-IFD ImageJ stacks (how Fiji saves stacks over 4 GB) return the first slices instead of the requested ones. |
| `ResampleTest/largeZarrWithDefaultBorderSize` | Large-file resampling with the default `borderSize` shifts every batch after the first by half an output voxel. |
| `StitchingTest/largeFileStitching`, `largeFileWithoutRegistration` | Large-file stitching fails (`XR_MIP_zarr.m:108` uses an undefined `bim`; MIP slabs only exist with `xcorrShift`). |
| `AutomaticProcessingTest/demoParameterSetIsAccepted` | The three `demo_microscope_pipeline_*.m` demos pass a 4-element `Save16bit`, which `XR_microscopeAutomaticProcessing` rejects. |
| `PointDetectionTest/lowSNRDetectionRuns` | `DetectionMethod='lowSNR'`, which all three point detection demos use, calls `crop_image_by_bounding_box`, which doesn't exist. |
| `PunctaRemovalTest/removesPunctaWithDefaultThresholds` | `XR_ExM_PunctaRemoval_zarr` with default thresholds builds an invalid task string (`%0.20d` with empty/vector thresholds), so default puncta removal never runs. |

**Platform-specific.** These tests skip themselves on the affected platform
with a `KNOWN ISSUE` message (`assumeNoKnownIssueOn`); remove the platform
from the call when the bug is fixed.

| Test | Platform | Problem |
|---|---|---|
| `TiffIOTest/readsSingleIfdImageJStack` | ARM macOS | The macArm Cpp-Tiff binaries read only the first slice of single-IFD ImageJ stacks (`getImageSize` reports 1 slice). |
| `ZarrIOTest/partialWritesUpdateOnlyTheRegion` | Windows | Rewriting existing zarr chunks keeps the old data: Cpp-Zarr renames a temporary file over the chunk, which fails on Windows when the chunk exists. |

Not covered by a test:

- On Windows and macOS, MATLAB hangs (Windows) or crashes in a thread
  cleanup handler (macOS) while shutting down after the PetaKit5D mex files
  have been used, most likely because an OpenMP runtime is unloaded while
  its worker threads are alive. CI works around it (see below).

- Dataset wrappers fail (`cd` error) when the repository folder path doesn't
  contain `PetaKit5D` (case-sensitive), or when a parent folder name contains
  it, e.g. `/data/my_PetaKit5D_tests/PetaKit5D`
  (`slurm_cluster_generic_computing_wrapper.m:55`,
  `generic_single_job_submit_wrapper.m:51`,
  `mcc_slurm_cluster_generic_computing_wrapper.m:61`).
- Point detection (`XR_runDetection3D`) fails on Windows: `getShortPath` splits
  paths with `regexp(path, filesep)`. These tests are skipped on Windows.
- Point detection doesn't work on ARM macOS: its mex files were never built
  for it (see `MexInventoryTest`).
- Deskew only (`deskew=true, rotate=false`) with the default
  `DSRCombined=true` writes DSR instead of DS, then waits ~3 minutes per retry
  before failing.
- `XR_deskew_rotate_data_wrapper` doesn't pass `jobLogDir` to the job
  framework, so Slurm job logs go to `../job_logs` (relative to the repository)
  or the data folder.

## Golden outputs

`tests/golden/GoldenOutputTest.m` runs the main algorithms (deskew/rotation,
deconvolution, PSF generation, stitching, point detection) on fixed synthetic
inputs and compares the results with reference outputs in
`tests/golden/data/*.mat` (relative L2 error <= 1e-4, which allows
floating-point differences between platforms but catches algorithm changes;
e.g., a 0.05 degree angle change or one extra RL iteration changes the
output by > 1e-3).

If you change an algorithm on purpose, regenerate the affected references on
Linux and commit them with the change:

```matlab
addpath tests tests/golden
update_golden_data('decon_omw')   % or update_golden_data() for all
```

## Writing tests

- Put tests under `tests/<area>/`, in a class that subclasses
  `pktest.TestCase` and whose name ends in `Test`. The base class puts
  PetaKit5D on the path, hides Slurm, seeds the random number generator,
  restores the current folder and warning state (some PetaKit5D functions
  change them), clears persistent caches, and closes figures the test opens.
- Generate inputs in the test (`pktest.beads`, `pktest.texture`,
  `pktest.writeStitchTiles`, ...) and keep them small (a few MB).
- Write files only under `testCase.createTempFolder()`; it returns a
  forward-slash path with a trailing slash, as the demos use.
- Always pass `parseCluster=false` to wrappers.
- Prefer exact or analytic checks (round trips, comparison with plain
  MATLAB code, known geometry) over stored numbers. Use
  `verifyImagesClose` with a justified tolerance where results are not exact.
- Keep tests portable: no shell commands, forward slashes in paths,
  `assumeMexAvailable` for mex files that are missing on some platforms, and
  `assumeNoKnownIssueOn` for bugs that only affect some platforms.
- Single-precision inputs to the deskew/rotation mex functions must have a
  first dimension that is a multiple of 8 until the SIMD overflow issue is
  fixed (see `DeskewMexSourceTest`).
