# The MATLAB tests in the port

Generated by `python tools/check_test_map.py docs` from `tests/matlab_map/` (the folder files with the task overlays in `fates/`) when changes are merged; tasks don't commit this file. Edit your task's overlay, not this file.

Every MATLAB test (class, method and parameterized case) has a fate: ported as a pytest test, covered by an oracle case, or not applicable with a reason. The area task named as owner fills its classes in `tests/matlab_map/fates/<TASK>.json` and marks them finished; CI (`tests/matlab_map/test_matlab_map.py`) fails when a test of a finished class has no fate.

Categories:

- `data`: data functions and wrappers (numeric and file level): ported in intent, numeric checks as oracle cases
- `framework_fake_slurm`: job logic against the fake Slurm: ported nearly one to one
- `framework_design`: framework tests tied to MATLAB's design (runners, pools, real cluster, isolation): ported to the Python design
- `matlab_only`: MATLAB-only mechanisms (mex fall-backs and packaging, path shadowing, mcc): not applicable
